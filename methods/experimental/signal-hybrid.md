# Signal Hybrid — extractor for magnitude, LLM for direction

**Status:** `candidate`（2026-10-24；单一被试、单一语料、n=40——按准入流程不得高于 candidate）
**Purpose:** 让 router 的信号提取在弱模型上同时获得准确的量级（counts）与有效的方向（风险感），
替代「全靠 LLM 自报」与「全靠关键词」两个各自失效的单一路径。

## 证据（Round 5 校准臂，40 道 IFEval 冻结选题，跨两个档位被试）

| 信号 | 来源 | `reflection/beam:free` | `z-ai/glm-5.3-flash` |
|---|---|---|---|
| `constraint_count` 量级 MAE | 关键词提取器 | **0.57** | **0.57**（同一提取器） |
| `constraint_count` 量级 MAE | LLM 自报 | 2.15 | **2.30** |
| 失败预测 AUC：自报 clarity（反） | LLM | **0.749** | 未测 |
| 失败预测 AUC：自报 hidden_constraint | LLM | **0.701** | 未测 |
| 失败预测 AUC：关键词 count / hidden | 提取器 | 0.602 / 0.596 | — |
| 朴素线性混合 | — | 0.683（不敌最佳单信号） | — |

结论：**量级失准跨模型成立**（免费档与 flash 档 MAE 2.15/2.30，都远差于提取器 0.57）；
方向信号只在 beam 上测过（AUC 0.70–0.75）。两条路径各管一半——提取器管基数，LLM 管方向；
朴素加权混合无效，必须按信号类型分配来源。

## 机制（提议）

`fillProfile` 混合模式：`constraint_count` 及一切可枚举信号取 `extract()`；`clarity` /
`hidden_constraint` / `error_cost` 的方向性估计取 LLM 自报（保留其 AUC 0.70–0.75 的风险感），
但以提取器的可枚举信号做幅度锚定（如 `hidden_constraint ≥ kwCount ≥ 3 ? 0.6 : self`）。

## 适用 / 不适用

- 适用：弱或中等模型的信号提取路径；任何「量级可数、方向需判断」的信号组合。
- 不适用（未验证）：强模型（自报量级可能本就准确，混合无增益）；非文本任务信号。

## 启动 / 停止条件

- 启动：进入 `fillProfile` 路径且被试自报量级 MAE 明显高于提取器（Round 5 于此触发）。
- 停止：混合版在第二语料/第二被试上量级或方向任一显著劣于单一路径。

## 成本 / 风险

- 成本：一次提取器调用（本地、零成本）+ 一次轻量自报调用（已有）。
- 风险：方向信号的 AUC 是单语料单被试结果，0.75 可能不迁移；锚定规则（上例）目前是拍脑袋的，
  未经搜索——**不得在验证前把锚定规则写进 core**。

## 待验证（下一步准入条件）

1. 第二语料（如 GSM8K 风格的数学题，truth=步骤数）复测双向 AUC/MAE。
2. 锚定规则做小网格（≤5 组）而不是单点拍定。
3. 对抗测试：构造「提取器数得出但方向感应错」与「方向感应对但数不出」两类探针各 ≥5 例。

## 失败模式记录

朴素线性混合劣于最佳单信号（0.683 < 0.749）——混合的第一失败模式就是「把分工做成加权」。
